# d8p OS

**A governed personal operating system built from sixteen focused repositories that work as one product.** d8p OS turns scattered information and recurring work into reusable workflows while keeping decisions, permissions, and human judgment visible.

## Why it exists

d8p OS is a laboratory for ongoing experimentation that also delivers practical, incremental value in daily life. It tests how content architecture, product governance, durable memory, agent workflows, and reusable automation can operate as one coherent system instead of a collection of disconnected tools.

The system stays useful by separating responsibilities. Management sets direction, publishing services shape inputs and outputs, domain applications keep work close to its records, and a shared platform supplies memory, skills, orchestration, administration, and consistent repository structure.

## Architecture

The operating model moves from direction to delivery to domain work, with the shared platform supporting every layer.

![d8p OS operating architecture: sixteen repositories arranged across governance, input and output, domain applications, and shared platform layers](./assets/d8p-os-stack-architecture.svg)

## Repository map

### Governance and direction

- **d8p-management** sets priorities, records decisions, governs the queue, and defines operating policy.

### Input and output

- **d8p-creative** turns strategy and source material into designed, publishable work.
- **d8p-newsroom** manages editorial intake, story development, and publishing flow.

### Domain applications

- **d8p-career** supports career strategy, opportunity discovery, and application work.
- **d8p-financehome** governs household finance and durable home records.
- **d8p-financehome-groceries** turns grocery intent into structured shopping workflows.
- **d8p-healthfitness** supports health, fitness, and lesson-based routines.
- **d8p-music** organizes listening, playlists, and music discovery.
- **d8p-family** keeps family coordination and records close to their context.
- **d8p-companion** provides a conversational surface across personal workflows.

### Shared platform and foundation

- **d8p-knowledge** is the governed knowledge vault and durable memory layer.
- **d8p-skills** owns reusable capability contracts and operating instructions.
- **d8p-admin** connects calendars, mail, tasks, and recurring operational rituals.
- **d8p-orchestrator** routes work across repositories and execution lanes.
- **d8p-scaffold** supplies the repository blueprint, shared baselines, and conformance checks.
- **d8p-obsidian-vault** preserves the legacy vault boundary while governed content transitions into the current model.

## Architecture model

| View | Purpose |
|---|---|
| **TOGAF system architecture** | Connects the architecture vision, business architecture, information systems, technology, migration plan, and cross-system concerns. |
| **arc42 component architecture** | Gives every repository the same twelve-section structure for goals, constraints, context, building blocks, runtime behavior, deployment, concepts, decisions, quality, risks, and glossary. |
| **Five documentation lanes** | Separates architecture, tutorials, how-to guidance, reference material, and explanation so people and agents can predict where knowledge belongs. |

## Public and private boundaries

This page is the public architecture snapshot. The repositories, working records, decision history, and detailed component documentation remain private so the system can safely contain personal operations and continue changing in the open-ended way a laboratory requires.
